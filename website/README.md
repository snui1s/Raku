# Raku website

Source of `https://raku.snui1s.com`: an Astro site with Tailwind, Starlight docs, a scroll-driven Three.js home page and a notebook you can write in. It is a separate project from the app, with its own `package.json`.

## Develop

Requires [Bun](https://bun.sh).

```bash
cd website
bun install
bun run dev        # local dev server
bun run test       # unit tests (release parsing, scene pieces)
bun run check      # type check
bun run build      # production build into dist/
bun scripts/check-build.ts   # sanity check of the built home page
```

## Structure

| Path | What it is |
|---|---|
| `src/pages/index.astro`, `src/components/` | Home page |
| `src/content/docs/docs/` | Docs (Markdown, served under `/docs/`) |
| `src/pages/privacy.astro` | Privacy policy |
| `src/lib/release.ts` | Reads `../update.json` at build time for the download button |
| `src/components/Journey.astro` | The whole home page: one pinned scene and the DOM placed over it |
| `src/scene/` | The 3D scene (Three.js), loaded only on capable desktop browsers. `journey.ts` is the scroll timeline |
| `src/notebook/` | The try-it notebook (TipTap, no React), loaded lazily |
| `src/pages/still.astro` | Page used only to render the hero images |
| `public/hero/` | Generated hero images (two sizes, `dark.*` and `dark-sm.*`) |
| `public/og.png` | The link-preview image (1200x630), generated by `scripts/render-og.ts` |
| `public/robots.txt` | Allows crawling and points at the sitemap; `/still/` uses a page-level `noindex` |
| `public/fonts/`, `src/styles/fonts.css` | Rubik (variable, Latin, upright and italic woff2), served from this site; no font is loaded from another host. Licence in `Rubik-OFL.txt` |

### Link previews and crawlers

Every page carries Open Graph and Twitter tags that point at `/og.png`: the home page and privacy page from `src/layouts/Base.astro`, the docs from the `head` list in `astro.config.mjs`. The image is the hero still with the name and tagline on a dark panel. After changing the hero (`bun run stills`) or the wording, regenerate it and commit it:

```bash
bun run og
```

This needs Google Chrome installed and reads `public/hero/dark.webp`. `robots.txt` lists the sitemap (`/sitemap-index.xml`, made by `@astrojs/sitemap`). `/still/` is excluded from the sitemap and has a `noindex` meta tag because it only exists to render the hero images. Crawling stays allowed so search engines can read that tag. `bun scripts/check-build.ts` fails if the og tags, `og.png` or the `robots.txt` sitemap line are missing from the build.

#### Search

The selling points the page and its metadata lead with are open source, offline, no account and fast. The home page's title, description and hero eyebrow say so, and `src/pages/index.astro` adds JSON-LD (`WebSite` and a free `SoftwareApplication` for Windows, with the version and installer URL from `update.json`; no rating or counts, which would have to be real). Docs pages get their titles and descriptions from the front matter of each Markdown file, so keep those specific. `check-build.ts` checks the title, description length and JSON-LD. Lighthouse on the built home page (mobile profile, which is what Google ranks on) scored 100 / 96 / 96 / 100 (performance / accessibility / best practices / SEO) on 2026-10-15. The hero picture is the page's largest paint, so it must not be `loading="lazy"`.

### Download button

`src/lib/release.ts` reads `update.json` from the repository root. The release workflow commits that file to `main` after each release, which triggers a Vercel deploy, so the button always points at the latest installer. If the file is missing or invalid, the button links to the GitHub Releases page.

### The home page

The home page always shows a pre-rendered image first. The live 3D scene mounts over it only when WebGL works **on a real graphics chip**, `prefers-reduced-motion` is off, the window is at least 768 px wide and the pointer is not touch. Otherwise the image stays and the page is plain sections in the same order (features list, notebook, numbers, download). On phones the picture fills the top of the first screen and fades into the page.

Software WebGL (SwiftShader, llvmpipe, Microsoft Basic Render Driver: virtual machines, remote desktops, machines without a graphics driver) counts as no WebGL: the context is requested with `failIfMajorPerformanceCaveat` and the renderer name is checked (`isSoftwareRenderer` in `capabilities.ts`). A scene that starts but is too slow gives up by itself: after the shader warm-up (about 4 s), if frames average over 100 ms, or over 60 ms with the resolution already at its lowest, it is taken down and the page becomes the plain one (`shouldGiveUp`). Add `?3d` to the URL to skip these checks and run the scene anyway (for trying a machine, or for tests under software GL), or `?plain` to see the plain page that machines without 3D get, without turning off your graphics (it is the same page, decided in the browser, so it has no separate address for search engines).

With the live scene the page is one tall section with a pinned frame, and scrolling drives a timeline (`src/scene/journey.ts`, lengths in screen heights):

1. **Hero**: the camera as in the still.
2. **Stars**: the camera tilts up into the night sky; each feature is a star with a label.
3. **Write**: the camera comes back down to the glade and holds while a notebook floats in front of the tree. It is a real editor.
4. **Numbers**: the camera pans over to the cherry tree; the four numbers hang under paper lanterns tied to its branches.
5. **Download**: the camera moves in on the fox, whose wooden tag (an *ema*) carries the Download link.

All text, buttons and the notebook are real DOM, placed over the canvas by projecting 3D anchor points to the screen every frame. To change the pacing edit `JOURNEY` and `CONSTELLATION` (scroll lengths); to move the camera edit `GLADE` and `TREE_VIEW` in `journey.ts` and `foxCamera` in `fox.ts`; the lanterns' branches and heights are `HANGS` in `lanterns.ts`.

Focusing something in another chapter (Tab) scrolls the page to that chapter first. The **Features** link in the nav goes to where the stars begin.

#### The notebook

`src/notebook/` builds an editor from the same TipTap extensions the app uses (headings, lists, checklists, highlight, color, quote) with a small toolbar. The page renders its sample note as plain HTML first and the editor takes over when the visitor nears it or touches it. Nothing is saved or sent anywhere; reloading clears it. It works with or without the live scene, including on phones.

#### Things to play with

With the live scene (not on phones), a few things respond to the pointer. None of it is needed to use the page, nothing is recorded, and the cursor turns into a hand over what can be clicked.

- **The fox** turns its head toward the pointer, and wags its tail and waggles its ears when clicked.
- **Wind from the pointer**: sweeping the pointer quickly across the scene makes a gust that bends the grass and flowers and blows the petals (`pushWind` in `wind.ts`).
- **The tree**: clicking it shakes it and a shower of blossom comes loose (`burstPetals` in `petals.ts`).
- **Stars**: clicking a star in the open sky sends a shooting star down from it (`shootingstar.ts`). Stars behind the hill, the gate, the tree or the fox cannot be clicked.

What is under a click is worked out in `mountScene` in `index.ts`, with the small testable parts in `interact.ts`.

The scene has the torii, a sakura tree, grass, falling petals, a river, a sitting fox, black-eyed Susans and poppies scattered over the hill, clouds, a moon, stars and wind gusts that move the grass, tree, petals and fox tail. Add `?fps` to the home page URL to see a readout of frame rate, draw calls and triangles.

After **any change to `src/scene/`**, regenerate the images and commit them:

```bash
bun run stills
```

This builds the site and renders `public/hero/*.webp|avif` with Google Chrome (it must be installed). No local web server is used. The script runs under Node 22.6 or newer (not Bun: on Windows Bun cannot talk to Chrome and the launch times out).

## Sizes (measured at build time on 2026-10-15)

- 3D (`scene.*.js` plus the shared Three.js chunk): about 620 KB raw, 162 KB gzip, 135 KB Brotli. It loads only when the live scene runs.
- Notebook (`mount.*.js`, TipTap and ProseMirror): 387 KB raw, 120 KB gzip, 102 KB Brotli. It loads when the visitor scrolls near the notebook or touches it, with or without the live scene.
- The scene draws about 260,000 triangles and 120 draw calls in the hero (measured in Chrome with software GL, so frame rate there means nothing), and about 70,000 while the camera looks up at the stars, because the flowers, the heaviest part, are skipped then. The flowers are about 150,000 triangles, the lanterns about 30,000, the fox about 4,000. `src/scene/budget.test.ts` fails if the flowers, lanterns, fox or the whole scene grow past their limits, so detail added later has to be paid for somewhere else.
- Frame rate on a real GPU has not been measured; use `?fps`.

## Deploy (manual steps for the repository owner)

1. In Vercel, import the `snui1s/Raku` repository.
2. Set **Root Directory** to `website/`. Framework preset: Astro. Build command `bun run build`, output `dist`.
3. In the project's **Settings, Domains**, add `raku.snui1s.com`.
4. At your DNS provider, add the record Vercel shows for that domain. For a subdomain this is normally a `CNAME` for `raku` pointing to `cname.vercel-dns.com` (use the exact value Vercel displays).
5. Wait for Vercel to issue the HTTPS certificate, then open the site.

Pull requests get preview deployments automatically. The `Website` GitHub Actions workflow builds and tests the site when `website/` or `update.json` changes.

## Security

Downloads accept only the exact installer URL generated by the release workflow, with matching version, release tag and filename in `snui1s/Raku`. Invalid metadata falls back to the repository's latest release page.

Astro emits a CSP in every built HTML page. `integrations/csp.mjs` also hashes inline tags emitted by trusted integrations such as Starlight. Scripts and stylesheets load from this origin; arbitrary inline scripts and JavaScript eval are blocked. Pagefind needs the narrower `wasm-unsafe-eval` permission for local search. Inline style attributes are allowed for 3D label positions, editor formatting and syntax highlighting; inline style elements still need a hash. The notebook's base CSS is bundled instead of injected at runtime.

`vercel.json` adds `frame-ancestors 'none'` and `X-Frame-Options: DENY` as HTTP headers on every path, plus `nosniff` and a referrer policy. Framing protection must be an HTTP header and is applied on the next Vercel deployment. Other hosts must supply equivalent headers. CSP is tested on production builds; Astro's dev server does not enforce it.

`postcss-selector-parser` is temporarily overridden to `7.1.6` for GHSA-rj75-hqrm-r3gf: the current Expressive Code dependency chain still requests 6.x. Revisit this override when its upstream dependency supports the patched parser. CI runs `bun audit` and validates every built page with `bun run check:security` after building.
