# Raku Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `raku.snui1s.com`: an Astro landing page with a lazy-loaded Three.js hero (torii, sakura, grass, petals), Starlight docs, and an auto-updating download button.

**Architecture:** A separate Astro project in `website/` (own `package.json`, Bun). The home page always renders a pre-rendered still hero first; a procedural Three.js scene mounts over it only on capable desktop browsers. The same scene code renders the stills headlessly. The download button reads `../update.json` at build time.

**Tech Stack:** Astro, Tailwind v4 (`@tailwindcss/vite`), Starlight, Three.js, Vitest, Playwright (stills only), sharp (image conversion), Bun, Vercel.

**Spec:** `docs/superpowers/specs/2026-10-14-website-design.md`. Visual reference for the scene: `mockups/landing-hero.html` (perspective torii and tree proportions).

## Global Constraints

- Site URL `https://raku.snui1s.com`, set as `site` in `website/astro.config.mjs`.
- English only; no analytics, cookies or third-party scripts; fonts self-hosted (LINE Seed copied from `src/assets/fonts` of the app).
- Palette matches the app: accent `#f25c54`, light bg `#faf9f7`, dark bg `#171717`; no gradients.
- Light and dark themes everywhere; the home page and Starlight share one theme choice (`localStorage` key `starlight-theme`, `data-theme` on `<html>`).
- 3D is hero-only. Live scene runs only when WebGL works, `prefers-reduced-motion` is off, width is at least 768 px and the pointer is not coarse. Otherwise the still stays.
- The app (`src/`, `src-tauri/`) is not modified. Root CI jobs must not depend on `website/`.
- Pinned dependency versions (no `^`) for `three`, `astro`, `@astrojs/starlight`; record the exact versions in `website/package.json`.
- Home page transfer target without the 3D chunk: about 250 KB; Lighthouse performance 90+ on desktop with the still showing.
- Download link falls back to `https://github.com/snui1s/Raku/releases/latest` when `update.json` is unusable.

## Review Focus

Input classes the spec implies that no feature task would otherwise test (each has a test in the owning task):

1. `update.json` present but with no `windows-x86_64.url`, a non-HTTPS URL, or a version that is not semver: the button must still work (Task 2).
2. WebGL context lost mid-session: the scene is removed and the still stays visible, no blank hero (Task 5).
3. Tab hidden, then shown; hero scrolled out of view, then back: rendering stops and resumes without time jumping, petals do not burst (Task 5).
4. Theme toggled while the scene is running, and on the Starlight docs pages: colors change live and the choice persists across pages (Tasks 3 and 5).
5. Window resize and changing `devicePixelRatio` (moving between monitors): canvas stays sharp and correctly sized, with the pixel ratio capped at 2 (Task 5).
