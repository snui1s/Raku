# 3D journey home page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (the owner chose native execution). Steps use checkbox syntax.

**Goal:** The home page is one pinned 3D scene driven by scroll: hero, constellation of features, a real notebook to write in, the four numbers as lanterns, and the Download link on a tag around the fox's neck.

**Architecture:** A pure `journeyAt(scrollVh)` timeline plus `journeyPose` for the camera extend the existing constellation code. The scene gets lanterns and a fox tag. DOM (notebook, numbers, download link) is placed over the canvas by projecting 3D anchors, as the feature labels already are. Without the live scene the same DOM falls back to plain sections.

**Tech Stack:** Astro 7, Three.js 0.186, TipTap 3 (no React), vitest, playwright-core (headless Chrome screenshots).

**Spec:** `docs/superpowers/specs/2026-10-15-3d-journey-design.md`

## Global Constraints

- Scroll 0 camera equals `CAMERA` exactly (stills are rendered from it); camera never rolled; path continuous.
- Notebook never saves or sends anything. English copy only. No `backdrop-filter` over the canvas.
- `data-download` link must keep pointing at `github.com/snui1s/Raku/`; SmartScreen note ("More info") stays in the HTML; `id="hero-scene"` stays.
- Phones, reduced motion, no WebGL: still picture then plain sections; the notebook works there.
- Do not touch the owner's uncommitted files (`.omphcache`, `INDEX.md`, `src/components/UpdateModal.tsx`); commit only website files; never push.

## Review Focus

- Typing into the notebook (incl. IME) while the scene runs; scroll keys stay with the editor.
- Focus (Tab) moving to a chapter other than the current scroll position.
- Fox tag readable and clickable at the final camera; sway does not move the link off the tag.
- Lanterns invisible in the hero view and in the stills until the numbers chapter.
- Live scene failing mid-way (onFail) leaves a working plain page.
